## Архитектура REAL PDA

### Что известно из публичного описания автора

Это не аудит кода. Это пересказ поста автора на Reddit (`r/stalker`, «REAL PDA Addon for Anomaly») и его комментария на ModDB. Поля протокола, имена Lua-функций, порты и формат пакетов оттуда **не следуют**.

Публично описанная схема:

```
Android-приложение
        │  домашняя Wi-Fi сеть, без интернета
        ▼
PC bridge (отдельная программа, не только Lua внутри игры)
        │
        ▼
игровой аддон Anomaly
```

Поведение, которое автор описал сам:

- Телефон подключается к PC bridge, bridge связан с игрой.
- В реальном времени синхронизируются маркер игрока и активные задания. Остальные вкладки обновляются периодически.
- Если игра зависла или упала, приложение не закрывается и держит последний снимок, который bridge успел записать.
- Карта: игрок, задания, тайники, точки интереса, ключевые маркеры, переходы между локациями, трупы, сквады.
- Контакты: известные персонажи и сквады.
- Справочник: энциклопедия, секции открываются по прогрессу.
- Радио: станции, плейлисты, prev/next, play/stop, громкость, repeat, shuffle.
- Сообщения: новости, задания, внутриигровой журнал.
- Управление картой: тап по заданию делает его активным; удержание маркера показывает детали; двойной тап по маркеру открывает fast travel; двойной тап по иконке игрока переключает GPS-режим.
- Набор маркеров зависит от модели PDA у персонажа.
- Настройки открываются по часам в правом верхнем углу.
- Пользователь в треде сообщил, что на Anthology 2.1 синхронизировалась карта, а задания — нет. Это симптом уже на Anomaly-сборке, до GAMMA.

### Что не установлено, потому что файлов нет

Нельзя назвать ни одного из следующих пунктов. Они обязательны для этапа 2, и их нельзя заменить догадкой:

1. PC-side часть: это Lua внутри `gamedata/scripts`, отдельный `.exe` bridge, оба слоя, или ещё и DLL.
2. Как игра отдаёт данные bridge: LuaJIT socket, файл-снимок, named pipe, shared memory, HTTP, сырой TCP/UDP.
3. Протокол: порт, handshake, формат кадра (JSON / бинарный / длина+payload), частота, кто клиент и кто сервер.
4. Список Lua/config-файлов аддона и какие callback Anomaly они цепляют (`actor_on_update`, `actor_on_info_callback`, task manager, map spots).
5. Android-side: язык, модули, модель данных, что приложение считает обязательным полем.
6. Есть ли уже карта как набор текстур локаций Anomaly или приложение рисует абстрактную сетку по координатам.
7. Как REAL PDA идентифицирует задания: строковый id Anomaly, id динамического task manager, имя функтора, id NPC-выдавшего.

Пока этих файлов нет, утверждение «протокол можно расширить» тоже непроверяемо.

## Архитектура соответствующих систем GAMMA 0.9.5

### Что известно публично и чего недостаточно

`Grokitach/Stalker_GAMMA` на `main` — это рецепт сборки, а не прошивка `gamedata`. Patchnotes прямо описывают **GAMMA 0.9.5** и перечисляют изменения, которые ломают ожидание «ванильный Anomaly PDA/quest API». Содержимое функций в этом отчёте не цитируется: соответствующих файлов в workspace нет.

По patchnotes 0.9.5 и modlist, PDA и задания в 0.9.5 собраны из нескольких аддонов, а не из одного `pda.script`:

- PDA Taskboard — iTheon.
- Custom iTheon's PDA Taskboard — lizzardman (другой UI поверх taskboard).
- New Tasks — iTheon.
- Tasks QoL Pack — Serious.
- G.A.M.M.A. Dynamic Tasks Balance.
- Fair Autocomplete Tasks Enhanced (FATE) — задания, которые «украл» другой сталкер, отменяются без штрафа.
- Guiding tasks видны на карте (SaloEater).
- PDA Map Location Labels and Faction Icons — mmmint.
- В patchnotes есть фиксы `pda.script` около строки 524, `task_functor` около строки 391, `tasks_measure`, `ui_inventory` около строки 2201.

Отсюда следует только одно инженерное ограничение, и оно подтверждено публичными patchnotes, не чтением Lua:

**GAMMA 0.9.5 не равно ванильной Anomaly в части заданий и PDA UI.** Динамические задания, taskboard, FATE и свои map-метки сидят поверх стандартного task manager. Аддон, который читает только ванильные task id / стандартные вкладки PDA, на 0.9.5 будет видеть неполную или другую картину. Это уже наблюдалось даже на Anthology: карта есть, задания нет.

### Что нельзя описать без файлов установки

Для каждой системы ниже нужен **выигравший override** из MO2-профиля именно GAMMA 0.9.5, а не копия из GitHub `main` (там может быть уже не 0.9.5) и не ванильный Anomaly.

| Система | Зачем она REAL PDA | Типичное место в установке GAMMA | Что прислать |
| --- | --- | --- | --- |
| PDA | Вкладки, журнал, модель PDA, какие маркеры вообще рисуются | MO2 mod, который переопределяет `gamedata/scripts/pda.script`, `ui_pda*.script`, `gamedata/configs/ui/pda_*.xml` | Выигравшие копии этих файлов плюс строка modlist, кто их перекрыл |
| Задания | Активные, описание, выдавший, цель, статус, провал | `task_manager.script`, `axr_task_manager.script`, `task_functor.script`, `tasks_*.script`, `sim_board.script`, taskboard-скрипты iTheon/lizzardman, FATE, `gamedata/configs/misc/task*.ltx` и `tm_*.ltx` | Те же файлы из mods, которые включены в профиле 0.9.5 |
| Игрок | Имя, id, здоровье, радиация, деньги, время | Скрипты, которые GAMMA вешает на actor binder и HUD статуса. Имена файлов в 0.9.5 не подтверждались | Скрипт(ы) actor status / body health из включённых модов и фрагмент, где читаются health, radiation, money |
| NPC | Контакты, группировки, отношения, маркеры | Скрипты squad/relation/gulag и PDA contacts, которые перекрыты GAMMA | `ui_pda_contacts.script` и relation/squad-скрипты победившего мода |
| Карта и маркеры | Локация, переход, направление, spots | `ui_pda_map.script`, map spots XML/LTX, level spot configs, аддон меток локаций | Эти файлы и каталог текстур карты, если REAL PDA их переиспользует |
| Тайники | Маркеры схронов | `treasure_manager.script` и конфиги treasure, которые GAMMA патчит (в репозитории GAMMA есть свой balance-патч) | Победившая копия |
| Инвентарь | Броня, оружие, патроны, вес, конечности. Read-only | `ui_inventory.script` и аддоны body health / loadout, которые 0.9.5 включает | Победившие скрипты и имя секции, откуда читается состояние конечностей |
| Сообщения | Новости, уведомления, PDA-журнал | News manager и PDA logs, которые рисует игровой журнал | `ui_pda_logs` / news-скрипт победившего мода |
| Сохранение | Снимок не должен ломать save | `bind_stalker.script` / save callbacks того скрипта, куда REAL PDA уже пишет своё состояние | Фрагмент save/load REAL PDA и тот же callback в GAMMA, если GAMMA его заменил |

Точные имена функций внутри этих файлов здесь намеренно не указаны. Их нужно прочитать в присланных копиях.

## Найденные несовместимости

Подтверждённые фактом «файлов нет» или публичными patchnotes. Не подтверждённые строками кода помечены как гипотезы и не являются заданием на правку.

### Подтверждено

1. **Нет общего дерева исходников.** Сравнивать API нечем. Это блокер, не пункт бэклога.
2. **REAL PDA закрыт.** Без локальной копии, которую вы положите в workspace, адаптер писать нельзя. Публичный клон протокола создавать не будем.
3. **GAMMA 0.9.5 меняет задания и PDA относительно Anomaly.** Patchnotes 0.9.5 описывают taskboard, dynamic task balance, FATE, видимые guiding-метки и отдельные фиксы `pda.script` / `task_functor` / `tasks_measure`. Аддон, собранный под ванильные task id, на 0.9.5 несовместим в слое заданий, пока не прочитан реальный task manager этой сборки.
4. **GitHub GAMMA `main` не является эталоном 0.9.5.** Репозиторий живой. Для адаптера нужна именно установленная 0.9.5, а не текущий `main` и не 0.9.6.

### Гипотезы, которые нельзя превращать в код до чтения файлов

- REAL PDA читает задания через стандартный Anomaly task manager и поэтому на GAMMA теряет dynamic/taskboard/FATE-задания. Похоже на симптом «на Anthology карта есть, задания нет», но без скрипта REAL PDA это не доказано.
- Координаты и уровень (`position`, имя уровня, игровое время, деньги, здоровье, радиация) отдаются движком и могут пережить GAMMA без патча `gamedata`. Это правдоподобно для движка Monolith, но имена биндингов в вашей сборке не проверены.
- Состояние конечностей, вес, броня и радио почти наверняка идут через GAMMA-системы, а не через ванильный PDA. Имена этих систем в 0.9.5 здесь не зафиксированы.
- Модель PDA, от которой зависит набор маркеров, в GAMMA может называться иначе или иметь другие секции предметов.

Пока гипотеза не подтверждена файлом, она не становится изменением.

## Какие файлы GAMMA затрагиваются

**Ни один файл GAMMA сейчас не изменяется.** В workspace их нет, и правило проекта — не трогать GAMMA, если хватает отдельного аддона.

После появления исходников допустимый максимум такой:

- Новый MO2-мод, который грузится **последним** и только дописывает callback или тонкий wrapper.
- Оригинальные файлы GAMMA не заменяются целиком.
- Если без правки существующей функции обойтись нельзя, правка делается копией функции в compatibility-аддоне (переопределение одного callback), с возможностью выключить мод в MO2 и вернуть поведение 0.9.5.

Список файлов GAMMA, которые вообще имеют смысл читать, — таблица выше. Список файлов, которые придётся менять, появится только после diff этих копий с тем, что вызывает REAL PDA.

## Какие файлы REAL PDA затрагиваются

Сейчас — никакие. Их нет в workspace.

Когда они появятся, предпочтительный объём правки:

- Не переписывать Android UI, карту, радио и протокол.
- На стороне игры добавить вызовы, которые отдают bridge те же структуры, которые приложение уже понимает.
- Если GAMMA отдаёт другие id заданий, перевод делается в адаптере на PC, а не новой схемой JSON в Android.

Какие именно файлы REAL PDA открывать, станет ясно по дереву его `gamedata` и по проекту Android Studio. Ожидаемые три корня, которые нужно прислать целиком:

1. Игровой аддон REAL PDA (`gamedata/**` этого мода).
2. Исходники или, если исходников bridge нет, сам bridge и любой имеющийся описание протокола / пример пакета. Без формата пакета этап 2 не начинается.
3. Android-проект (модуль, который парсит сообщения от bridge).

## Какие изменения необходимы

Сейчас необходимо только одно: положить исходники в workspace. Кодовых изменений нет.

После чтения файлов необходимые изменения, в этом порядке:

1. Зафиксировать реальный протокол REAL PDA (кадр, порт, кто слушает) и не вводить второй.
2. Отдельный MO2-аддон `REAL PDA GAMMA 0.9.5 compatibility`, который можно снять.
3. Тонкий слой чтения: игрок (имя/id, уровень, позиция, время, здоровье, радиация, деньги) в том формате, который bridge уже шлёт.
4. Логи четырёх участков: игра, адаптер, сеть bridge, то что ушло в сторону Android.
5. Дальше по приоритету из задания: карта и маркер, задания через адаптер id, NPC, инвентарь read-only, сообщения. Каждый слой — отдельный commit и только после проверки предыдущего.

## Какие изменения не нужны

- Новый протокол, новый APK и новая карта, если REAL PDA это уже умеет.
- Правки ванильных и GAMMA-файлов «на всякий случай».
- Замена `pda.script`, taskboard, FATE, инвентаря или новостей GAMMA.

## Предполагаемая архитектура compatibility layer

Это контур, не реализация. Имена модулей можно сменить, когда станет виден стиль REAL PDA. Пока неясно, лежит ли мост в Lua или в отдельной программе, адаптер должен сесть **между игрой и уже существующим сбором данных REAL PDA**, а не рядом вторым сокетом.

```
Android-приложение REAL PDA
        │  существующий протокол, без новой схемы
        ▼
PC bridge REAL PDA
        │
        ▼
существующий сборщик REAL PDA для Anomaly
        │
        ▼
GAMMA 0.9.5 compatibility addon   ← новый, снимается в MO2
        │  RealPdaPlayerAdapter
        │  RealPdaMapAdapter
        │  RealPdaQuestAdapter
        │  RealPdaNpcAdapter
        │  RealPdaInventoryAdapter
        │  RealPdaMessageAdapter
        ▼
GAMMA 0.9.5 Lua/API (читаем, не подменяем системы)
```

Адаптер заданий — единственный, который почти наверняка обязателен: он должен переводить dynamic/taskboard/FATE-задания GAMMA 0.9.5 в ту структуру, которую REAL PDA уже кладёт в пакет. Остальные адаптеры добавляются только если прямой вызов движка или ванильного скрипта на 0.9.5 не совпадает с тем, что читает REAL PDA.

Логи, которые понадобятся, когда появится код:

- connection log REAL PDA (handshake, обрыв, последний снимок);
- adapter log (какой адаптер, какой источник GAMMA, что отдал);
- network log (направление, размер, тип сообщения, без попытки логировать лишние бинарные дампы в горячем кадре);
- player sync log;
- quest sync log;
- ошибки с меткой участка: `PC game` / `GAMMA` / `adapter` / `REAL PDA bridge` / `Android`.

Отдельный файл лога в `appdata` или рядом с bridge, чтобы его было видно без консоли движка. Точный путь выберется по тому, куда REAL PDA уже пишет свой лог.

## Порядок реализации

Реализация не начата. Порядок после разблокировки:

1. **analysis** — этот документ. Следующая ревизия допишет сюда реальные имена файлов, функций и несовместимости со ссылками на строки.
2. **compatibility layer** — пустой MO2-аддон и логгер, игра запускается, стандартный PDA GAMMA не задет. Без сокета, если протокол ещё не прочитан.
3. **player sync** — семь полей первого прототипа в существующий пакет.
4. **map sync** — локация, позиция, направление, маркеры, переход. Через карты REAL PDA.
5. **quest sync** — адаптер GAMMA → формат заданий REAL PDA.
6. **inventory sync** — read-only.
7. **NPC sync**.
8. **messages**.
9. **testing** — чеклист из задания на каждой из предыдущих ступенек, отдельным коммитом фиксируются найденные ошибки и правки.
10. **documentation** — `README_GAMMA.md` и `GAMMA_COMPATIBILITY.md`.

Проверка «запускается ли GAMMA» из этой VM невозможна: клиента Anomaly здесь нет. Её можно сделать только на вашей установке. Скриптовую проверку (синтаксис Lua, отсутствие правок чужих файлов, что аддон выключается удалением одной папки) можно сделать здесь, когда файлы появятся.

## Потенциальные проблемы

- Закрытый bridge. Если в поставке только `.exe` без описания пакетов, расширить протокол нельзя, не ломая приложение. Тогда работа останавливается на границе «какие байты bridge уже принимает».
- MO2 override. Любой наш скрипт с тем же именем, что у GAMMA, заменит систему целиком. Аддон должен использовать новые имена файлов.
- Двойной taskboard. iTheon и custom lizzardman оба претендуют на вкладку заданий. Читать нужно тот, который включён в профиле 0.9.5.
- FATE отменяет задание без штрафа. Статус «провал» и «отмена, потому что награду забрал другой» для REAL PDA могут быть одним и тем же полем. Это надо сверить с приложением, а не склеить молча.
- `pda.script` в 0.9.5 уже патчился из-за падений. Лишний хук в этот файл опаснее, чем отдельный callback-скрипт.
- Частота синка. Автор сам вынес в realtime только маркер и активные задания. Тянуть инвентарь и контакты каждый кадр нельзя.
- Сохранения. Если адаптер пишет глобальные таблицы в сейв, снятие мода сломает загрузку. Состояние адаптера не должно быть обязательным для сейва GAMMA.
- Версия. Патч под 0.9.6 или под сегодняшний `main` может разъехаться с вашей установкой. В документации версия будет прибита к 0.9.5 и к конкретным именам модов из вашего `modlist.txt`.

## Что нужно положить в workspace

Без этого этап 2 не начинается.

### 1. REAL PDA, игровой аддон

- Зачем: увидеть, как мод забирает данные из Anomaly и какие скрипты вообще существуют.
- Куда обычно ставится: отдельный мод MO2 или папка `gamedata` поверх Anomaly. Имя папки зависит от установщика MUZZPAD.
- Что прислать: весь каталог мода, особенно `gamedata/scripts`, `gamedata/configs`, `gamedata/configs/text`.

### 2. PC bridge и протокол

- Зачем: не создавать второй канал связи. Android уже говорит с этим bridge.
- Куда обычно ставится: рядом с игрой или внутри папки мода, отдельной программой. Точное имя бинарника без вашей установки неизвестно.
- Что прислать: исходники bridge, если они у вас есть. Если есть только программа — её каталог и любой лог/пример сообщения, по которому виден формат. Участок, без которого нельзя продолжать: handshake и структура пакета с позицией игрока и активным заданием.

### 3. Android-проект

- Зачем: сверить имена полей, которые приложение уже парсит.
- Куда обычно ставится: проект Android Studio, не APK.
- Что прислать: модуль, который читает сокет/HTTP bridge. Достаточно пакета модели данных и парсера, не всего UI.

### 4. GAMMA 0.9.5, только выигравшие скрипты

- Зачем: сравнить реальный API 0.9.5 с вызовами REAL PDA.
- Где лежит: `ModOrganizer/mods/<включённый мод>/gamedata/...` и профиль `modlist.txt`. Не присылайте весь Anomaly.
- Что прислать в первую очередь, одним архивом с сохранением путей:
  - `modlist.txt` профиля GAMMA 0.9.5;
  - `pda.script`, `ui_pda.script`, `ui_pda_map.script`, `ui_pda_contacts.script`, скрипт журнала PDA;
  - `ui_pda_taskboard_tab.script` и соседние скрипты taskboard из включённого мода;
  - `task_manager.script`, `task_functor.script`, динамический task manager, FATE-скрипт, если он включён;
  - скрипт состояния игрока и конечностей из включённого body-health мода;
  - `treasure_manager.script`;
  - news/logs скрипт журнала сообщений.
- Участок кода, который нужен первым: функции, которые отдают активные задания, позицию актора, имя уровня и деньги. После них — map spots и контакты.

Положите это в workspace как есть, например:

```
/workspace/vendor/real-pda/
/workspace/vendor/gamma-0.9.5/
```

Оригиналы GAMMA оттуда читаются и не редактируются. Новый аддон будет жить отдельно.

## Первый минимальный прототип

Его ещё нет. Он начнётся только после чтения bridge и игрового скрипта REAL PDA.

Задуманный объём, без расширения протокола:

Android подключается к уже существующему PC bridge и получает семь полей из GAMMA 0.9.5:

- имя или id игрока;
- текущая локация;
- координаты;
- игровое время;
- здоровье;
- радиация;
- деньги.

Карта, задания, NPC, инвентарь и сообщения в этот прототип не входят. Если эти семь полей уже есть в пакете REAL PDA, прототип — это только наполнение того же пакета из GAMMA. Если какого-то поля в протоколе нет, оно не добавляется новым сообщением, пока не будет видно, куда приложение его положит.
