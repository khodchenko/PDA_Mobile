# Внешний PDA для Anomaly и GAMMA

Статус: пункты 1 и 2 сделаны в коде, пункт 2 ждёт проверки в настоящей игре. Пункт 0 совмещён с пунктом 2: экспортёр сам проверяет папки записи и пишет `pda_report.txt`. Телефон пока веб-страница от моста, `android/` не создавался.

Дата: 2026-10-07.

Решение: не адаптировать MUZZPAD / REAL PDA. Своего исходного кода у этого проекта нет, публичная сборка с ModDB снята, протокол закрыт. Декомпилировать его не будем. Делаем свой комплект: игровой аддон, PC-мост, Android-приложение.

Цель первого рабочего среза: телефон в домашней сети показывает живые данные из запущенной игры. Интернет не нужен.

## Ограничение движка, из-за которого мост снаружи

В `script_storage.cpp` X-Ray Monolith сокетная библиотека Lua открывается только при `lua_debug`. Обычная сессия GAMMA её не поднимает. `os.execute`, `os.remove`, `io.popen` вырезаны. `io` остаётся, писать файлы через пути `getFS()` можно. FFI в этих exe есть, но сокет из кадра игры через FFI легко вешает кадр. Поэтому игра не слушает порт.

Так уже сделано в Xray-TPC: Python снаружи, Lua только читает файл очереди. У них очередь лежит внутри `gamedata/scripts`, и MO2 это ломает, потому что игра видит VFS, а Python видит диск.

Наш мост лежит **вне** VFS. Игра пишет снимок в каталог, который существует на диске и в профиле MO2 одновременно. Телефон говорит только с мостом.

```
Android
   │  домашняя сеть, HTTP + WebSocket, код сопряжения
   ▼
PC-мост (процесс на компьютере, порт только LAN)
   │  читает снимок, кладёт команды в ящик
   ▼
аддон MO2, только свои .script
   │  Anomaly-читатель и GAMMA-читатель
   ▼
Anomaly 1.5.3  или  GAMMA 0.9.5
```

Игровые файлы GAMMA не перезаписываются. Аддон выключается снятием одной папки в MO2.

## Протокол

Свой, версионированный JSON. Не совместим с MUZZPAD и не обязан быть.

- Снимок состояния: игра → файл → мост → телефон.
- Команды: телефон → мост → файл-ящик → игра. Пока только белый список, каждая команда именованная. Произвольного кода нет.
- Частота. Поза игрока 5–10 раз в секунду. Задания, инвентарь, контакты и сообщения — по изменению или раз в секунду. Не каждый кадр.
- В каждом снимке есть `protocol`, `time_ms`, имя уровня и признак, какой читатель его собрал: `anomaly` или `gamma`.
- Если поле не прочиталось, оно отсутствует, и в лог пишется имя источника. Мост не подставляет нули «чтобы экран не был пустым».

- Два файла, а не один. Быстрый: поза, здоровье, время. Медленный: задания, инвентарь, контакты, сообщения, каждый блок со своей версией. Иначе ради 10 Гц маркера придётся каждый раз заново сериализовать весь инвентарь.
- В снимке есть `capabilities`: какие блоки этот читатель реально умеет отдавать в этой сессии. Телефон по нему решает, показать вкладку или написать «в этой сборке недоступно». Отсутствующее поле само по себе не объясняет, сломалось оно или не поддерживается.
- Состояние игры отдельным полем: `menu`, `loading`, `in_game`, `dead`. Плюс heartbeat. Телефон различает «мост не отвечает», «игра не пишет снимки» и «игра на загрузке» и показывает это словами, а не застывшим экраном.
- Команды с `id`. Игра подтверждает выполненные id в следующем снимке, поэтому повтор после обрыва не выполнит команду дважды. Ящик команд игра читает 2 раза в секунду, а не каждый кадр.
- Схема протокола описывается один раз в JSON Schema. Из неё проверяются фикстуры моста и генерируются типы для телефона.
- JSON-кодировщик в Lua свой и маленький. Надеяться на библиотеку из чужого мода нельзя.

Телефон не ходит в интернет. Мост по умолчанию слушает локальную сеть, не `0.0.0.0` в открытый интернет. Сопряжение: мост показывает на ПК QR-код с адресом, портом и одноразовым токеном, телефон его сканирует. Ручной ввод IP и кода — запасной вариант. Без токена снимок не отдаётся. В документацию — запрос брандмауэра Windows при первом запуске, иначе первое «не подключается» будет именно из-за него.

## Что именно синхронизируем

Порядок такой, потому что каждый следующий слой зависит от предыдущего и от файлов GAMMA, которых здесь до сих пор нет.

1. Соединение. Телефон видит мост, мост видит, что игра жива.
2. Игрок: имя или id, уровень, координаты, игровое время, здоровье, радиация, деньги.
3. Карта текущей локации и маркер игрока, направление, переходы.
4. Задания: активные, название, описание, кто выдал, цель, маркеры, статус, завершение и провал.
5. NPC и контакты: группировки, отношения, известные люди, маркеры, точки интереса.
6. Инвентарь, только чтение: конечности, броня, оружие, патроны, деньги, вес, список предметов.
7. Сообщения, уведомления, новости, журнал ПДА.
8. Команды с телефона (сделать задание активным, радио) — после того, как чтение стабильно.

Картинки карт из игры не кладём в репозиторий. Мост отдаёт их с диска пользователя на телефон по LAN. Пока нет таблицы «имя уровня → текстура и прямоугольник карты», телефон показывает имя уровня и координаты без подложки. Таблицу заполняем из LTX установленной игры, не по памяти.

Задания GAMMA не читаем через ванильный список вслепую. Два читателя за одним интерфейсом:

- `anomaly` — то, что отдаёт обычный task manager 1.5.3;
- `gamma` — taskboard, динамические задания и FATE, когда появятся выигравшие скрипты 0.9.5.

Читатель выбирается не по строке версии, а по тому, что реально загружено в этой сессии: есть ли нужные скрипты и глобалы. Тогда один аддон работает и на чистой Anomaly 1.5.3, и на GAMMA, и на сборке, где taskboard выключен. Номер версии GAMMA пишем в лог для диагностики, но решения на нём не строим.

Если глобала GAMMA нет, читатель пишет в лог «источник не найден» и отдаёт пустой список. Игровой ПДА при этом не трогается. Статус «отменено, потому что награду забрал другой» (FATE) не склеиваем с провалом, пока не увидим реальное поле.

Имена функций в этом плане намеренно не зафиксированы. Первый Lua-модуль вызывает кандидатов через `pcall` и логирует, какой из них есть в этой сессии. Кандидаты первого дня: объект актёра, позиция, здоровье, деньги, имя уровня, игровое время, радиация. Чего нет в конкретной сборке, то не выдумывается.

## Состав репозитория, когда начнём код

```
addon/          MO2-мод, только новые имена файлов
bridge/         Python 3, позже один exe, чтобы не ставить Python
android/        Kotlin, Android Studio
docs/           установка, порты, ограничения
```

Логи четыре, чтобы было видно место обрыва:

- игра: что смогли прочитать;
- адаптер: anomaly или gamma, какое поле пустое;
- мост: файл обновился или нет, кто подключился, размер снимка;
- телефон: какой снимок показан.

Цепочка в сообщении об ошибке: `game → adapter → bridge → android`.

Состояние моста в сейв не пишется. Снятие аддона не должно делать сохранение GAMMA незагружаемым.

Lua проверяется не только синтаксисом. Экспортёр гоняется под LuaJIT вне игры с заглушками движка: на выходе должен получаться валидный по схеме снимок. Это ловит ошибки до того, как пользователь запустит GAMMA.

## Открытый вопрос: сначала нативное приложение или веб-экран

Предложение: первый срез телефона сделать веб-страницей, которую отдаёт сам мост, с установкой на главный экран Android. Без Android Studio, без сборки и подписи APK, обновляется вместе с мостом, заодно работает на планшетах и iPhone. Нативную оболочку на Kotlin делать вторым шагом, когда понадобится то, чего браузер не умеет: работа в фоне, экран не гаснет надёжно, уведомления при заблокированном телефоне, вибрация на событие.

Решение за владельцем проекта. Пока оно не принято, в `android/` ничего не создаём, а протокол не делаем зависимым от выбора.

## Порядок работ

0. Проверка канала на реальной игре, до телефона. Крошечный аддон раз в секунду пишет счётчик в файл. Проверяем три пути: абсолютный путь вне папки игры, `overwrite` профиля MO2 и каталог сохранений через `getFS()`. Заодно пишем в лог, есть ли `os.getenv`, `io.open` на запись и сколько стоит запись. Это главный риск всего плана: если канал не работает, остальное не имеет смысла.
1. Протокол и фиктивный снимок. Мост отдаёт его на LAN. На телефоне экран игрока без игры. Это проверяется здесь. Вместе с ним — запись и проигрывание снимков, чтобы телефон и мост можно было гонять без запущенной игры.
2. Lua-экспортёр семи полей игрока в файл. Пользователь кладёт аддон в MO2 и один раз указывает мосту папку профиля. Проверка запуска GAMMA, обычного ПДА, сейва и фризов — на его машине. Здесь клиента нет.
3. Карта и маркер. Сначала координаты, потом подложка из его установки.
4. Читатель заданий Anomaly и пустой читатель GAMMA с логом. Настоящие поля GAMMA дописываются, когда в workspace лежат выигравшие скрипты 0.9.5: taskboard, task manager, FATE, `modlist.txt`.
5. Инвентарь, только чтение.
6. NPC и контакты.
7. Сообщения.
8. Команды с телефона.
9. Упаковка моста в exe и короткая инструкция установки поверх GAMMA 0.9.5.

Коммиты мелкие, по этим пунктам, не одним куском.

## Что сознательно не делаем

- Второй протокол «на всякий случай» и совместимость с MUZZPAD.
- Правки `pda.script`, taskboard, инвентаря и новостей GAMMA.
- Слушающий порт внутри игры и удалённое выполнение Lua.
- Управление инвентарём с телефона в первых срезах.
- Раздачу текстур карт и строк энциклопедии внутри нашего репозитория.
- Привязку к сегодняшнему `main` GAMMA и к ещё не вышедшей 0.9.6.

## Риски

- Путь снимка под MO2. Игра может писать в `overwrite` профиля, а мост смотреть в папку Anomaly. Лечится одним явным путём в настройке моста, не угадыванием.
- Запись файла. Если `io.open` в этой сборке не пишет туда, куда мы ожидаем, первый запуск это покажет логом. Запасной путь — каталог сохранений через `getFS()`. Сокет из Lua не включаем, пока файловый канал не признан мёртвым на реальной GAMMA.
- Задания 0.9.5. Без скриптов taskboard и FATE читатель GAMMA честно пустой. Это не баг экрана.
- Карта. Без LTX границ локации маркер на картинке врёт. До чтения конфига картинку не показываем.
- Нагрузка. Снимок реже кадра. Тяжёлые списки только по изменению. Бюджет Lua на тик меряем и пишем в лог с первого среза, а не после жалоб на FPS.
- Обрывок файла. `os.rename` в Monolith вырезан, атомарной замены через переименование нет. Мост принимает снимок, только если JSON целый и `seq` в начале совпадает с `seq` в конце. Иначе берёт прошлый снимок и пробует на следующем опросе.
- Текстуры карт лежат в `.db`-архивах Anomaly, а не отдельными файлами. Мосту нужен импорт из установки пользователя. Чем распаковывать, проверяем до среза с картой.
- Антивирус. Python, собранный в один exe, часто ловит ложные срабатывания, а у игроков GAMMA антивирус и так мешает установке. Перед упаковкой сравниваем с одним бинарником на Go.
- Проверка. Запуск GAMMA, сейв, обычный ПДА и FPS из этой среды не проверяются. Синтаксис Lua и мост с фиктивным снимком проверяются здесь.
- Linux и Steam Deck. Часть игроков GAMMA запускает её через Proton или Heroic. Мост тогда работает на самом Linux, а путь из игры выглядит как путь Windows внутри префикса. Перевод путей описываем в документации, а не узнаём из багрепорта.
- Несколько сейвов и персонажей. В снимке есть идентификатор персонажа и сессии, чтобы телефон не смешал данные после загрузки другого сохранения.

## Что нужно от установки, и без чего можно начать

Без игры можно сделать пункт 1: мост, протокол, экран телефона на фиктивных данных.

Для пункта 2 нужен профиль GAMMA 0.9.5 или чистая Anomaly 1.5.3, куда кладётся аддон. Для заданий, карты и инвентаря по-прежнему нужны выигравшие файлы, а не весь архив на десятки гигабайт:

- `modlist.txt` профиля;
- скрипты ПДА и taskboard, которые реально включены;
- task manager, динамические задания, FATE, если включён;
- конфиг карт уровней (границы и текстура);
- скрипт состояния тела и инвентаря.

Их кладём в `vendor/gamma-0.9.5/`, читаем, не редактируем.
